# M6-T003 备份、恢复与回退

生产主机每天以受限运维账户执行 `deploy/ops/backup.sh`。它通过 MySQL 的一致性逻辑备份、MinIO 对象镜像、SHA-256 清单和按天保留策略生成不可混淆的恢复点。`BACKUP_DIR` 必须位于加密、非仓库、非容器卷的存储；`BACKUP_RETENTION_DAYS` 默认 14。

恢复必须使用 `restore.sh <UTC备份编号> <MYSQL_DATABASE>`，并输入脚本显示的完整确认短语。该动作会停止后端、校验备份、替换明确指定的数据库、回灌对象存储后再启动后端。迁移失败时禁止手改 `pxczxn_schema_version`：回退代码或从最近恢复点恢复数据库，再在隔离环境复盘 SQL。

旧版本仅通过 `rollback-release.sh <已批准提交>` 回退应用镜像/代码，刻意不回退数据库。若版本包含不可兼容数据迁移，应先完成数据库恢复演练并选择与备份匹配的代码提交。

Redis 演练只允许在 staging 使用 `redis-fact-drill.sh`；它要求确认短语，在清空缓存前后比对 MySQL 的用户、文章和动态计数，以证明 Redis 不承载核心事实。每次演练将终端输出、备份编号、恢复耗时和健康检查结果记录到受控运维工单。
