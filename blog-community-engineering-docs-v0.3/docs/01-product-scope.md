# 01 产品定位、范围与路线图

## 1. 产品定位

平台定位为：

> 免费、开放但有秩序的博客社区。

核心体验：

```text
注册账号 = 获得一个个人博客
```

个人博客不是附属空间，而是用户唯一公开主页。社区负责连接不同个人博客和团队博客，提供发现、互动、关注、投稿、共创和内容治理能力。

## 2. 目标用户

- 技术作者与项目开发者
- 学生和学习记录者
- 写作爱好者
- 设计师、创作者和团队
- 希望拥有长期内容主页的普通用户

平台不局限于技术内容，因此默认编辑器必须对普通用户友好。

## 3. 当前 V1 基线（已完成）

V1 的完成边界是 M1 基础发布闭环与 M2 社区互动闭环，另已按产品决定补充即时聊天模块。

### 用户、博客与内容

- 注册、登录、退出、账号安全和个人博客自动创建
- 个人博客资料、三色主题、分类、平台标签和社区文件
- 富文本与 Markdown 草稿、版本、审核、立即/手动/定时发布和公开访问
- 管理端文章审核、标签管理、内容运营与 RBAC

### 社区互动与沟通

- 关注、粉丝、互关、特别关注、喜欢、收藏夹
- 文章/动态的评论、回复、点赞、收藏、分享、转发和引用
- 站内通知、未读计数，以及评论和动态的基础运营治理
- 单聊、群聊、聊天成员管理、未读状态与 WebSocket Ticket 鉴权

### 当前明确不进入 V1 的能力

- 团队申请、团队成员角色、投稿、系列和文章共创（M3）
- 举报、屏蔽、申诉、完整处罚与反滥用体系（M4）
- 统一搜索、可解释发现排序、RSS、完整 SEO、创作者统计与性能专项（M5）
- 公网生产部署、CI/CD、备份恢复、监控和灰度开放（M6）
- 付费、钱包、结算、原生视频/直播、实时多人编辑、复杂 AI 推荐、开放 API、插件市场、多语言和原生 App

## 5. 商业模式

V1 及可预见阶段不收费。

不通过限制正常功能制造付费点，不开发支付、钱包和结算模块。未来只有出现明确、合法且可持续的收入来源后，才重新评估商业化。

## 6. 正式阶段路线图

### M1：基础发布闭环

```text
注册 → 自动创建个人博客 → 写文章 → 提交审核 → 发布 → 公开访问
```

### M2：社区互动

关注、评论、点赞、收藏、通知和动态。已完成。

### M2.5：产品语义与信息架构校正

- 新增真实 `/discover`：推荐、最新、热门、关注四类可解释内容流，文章与动态混合展示；补齐推荐博客、热门标签、热门系列、编辑精选、搜索和创作入口。
- 无推荐算法时只能使用编辑精选、最新发布、互动热度和关注内容；不得伪装为“智能推荐”。
- 未登录访问平台与无 `returnTo` 的登录成功页统一落到 `/discover`；个人博客继续固定在 `/blogs/{slug}`，不再承担平台首页职责。
- 博客端正式导航为：首页、发现、文章、动态、系列、团队、标签；个人入口为写文章、通知、聊天、我的博客、收藏夹、设置。
- 原型硬编码路由改为 `/moments/{momentId}`、`/teams/{teamSlug}`、`/collaboration/articles/{articleId}`；示例仅允许作为种子数据。
- 管理端改为社区运营中心：运营总览、用户与博客、内容管理、审核中心、社区治理、团队管理、标签与系列、通知管理、即时聊天、数据分析、系统设置；平台人员与权限归入系统设置。
- 清理 Mars、OA、公司管理和无意义测试文案，统一为星语社区平台、平台运营组、内容审核组、社区治理组、技术运维组。

### M3：团队内容

- 团队博客申请审核、团队创建和 OWNER 初始化。
- 邀请、接受/拒绝、退出、移除、角色调整、所有权转让和解散；业务角色固定为 OWNER、ADMIN、EDITOR、AUTHOR，不进入 `sys_role`。
- 团队权限引擎同时判断团队、成员身份、角色、资源归属和资源状态。
- 真实团队主页 `/teams/{teamSlug}` 与角色感知工作台 `/workspace/teams/{teamId}`。
- 固定文章版本的外部投稿闭环、系列与连载、联合创作署名关系。

### M4：治理与运营

- 举报文章、动态、评论、博客、用户、团队和聊天内容；支持理由和证据。
- 用户屏蔽、博客/标签/聊天屏蔽及其在推荐、评论、动态、私聊和通知中的一致效果。
- 申诉中心、可审计处罚体系、关键词规则、风险动作和反滥用限制。
- 运营治理数据：举报量、处罚量、申诉通过率、风险趋势、处理时效和操作日志。

### M5：体验与增长

- MySQL 优先的统一搜索：文章、动态、个人/团队博客、系列、标签和用户。
- 可解释发现排序和关注内容流；排序因子包含时间、互动、内容质量和风险状态。
- 专题、活动、公告、编辑精选和内容合集。
- 博客/系列/标签/全站精选 RSS，Meta、Open Graph、Canonical、Sitemap、robots 与结构化数据。
- 创作者阅读、互动、粉丝、内容表现、流量来源和搜索词统计；图片、缓存、静态化、分包、索引和性能指标优化。

### M6：公网发布与持续运营

- 域名、HTTPS、MySQL、Redis、OSS/MinIO、Nginx、Docker Compose、环境变量与日志轮转。
- CI/CD 覆盖后端测试、双前端检查、迁移校验、安全扫描、E2E、镜像构建和部署审批。
- 数据库/文件备份、回滚、迁移失败恢复和 Redis 清空降级验证。
- 服务、错误率、数据库、磁盘、内存、慢查询、登录异常、审核/通知积压监控告警。
- 个人测试 → 邀请用户 → 限量开放注册 → 正式开放的灰度流程。

## 7. 阶段完成要求

每个阶段必须依次完成需求与数据设计、后端业务、博客端、管理端、自动化测试、真实浏览器 E2E、交付文档与独立提交。详细任务拆分见仓库 `docs/delivery/M2.5-M6-task-breakdown.md` 与 `docs/planning/M2.5-M6-delivery-plan.md`。
