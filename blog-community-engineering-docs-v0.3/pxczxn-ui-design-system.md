# pxczxn 博客社区 UI 设计规范

> 文档状态：V1 UI 基线  
> 适用范围：`pxczxn-web` 用户端、`pxczxn-admin` 管理端  
> 设计目标：现代、清晰、克制、适合长时间阅读，同时保留独立的星空品牌氛围

---

# 1. UI 总体原则

项目 UI 遵循以下原则：

1. 内容优先，阅读体验优先于装饰效果。
2. 博客端与管理端使用不同的视觉表达，但共用基础品牌色和状态色。
3. 浅色、深色、星空色为三套独立主题。
4. 星空色不是深色主题贴背景图，而是独立品牌主题。
5. 组件状态必须完整，包括默认、Hover、Active、Focus、Disabled、Loading、Error。
6. 页面结构统一，避免每个页面各自发明布局。
7. 不为了炫技加入过多玻璃拟态、发光、渐变和动画。
8. 不允许 AI 或开发人员随意修改核心间距、圆角和颜色语义。
9. 移动端不是桌面页面简单缩小，必须重新组织布局。
10. 所有视觉实现应优先保证可读性、可访问性和一致性。

---

# 2. 前端 UI 技术边界

## 2.1 用户端 `pxczxn-web`

技术栈：

```text
Next.js
React
TypeScript
Tailwind CSS
Ant Design React（按需使用）
```

使用原则：

- 页面布局、博客主页、文章卡片、内容流、文章详情等视觉主体，使用 Tailwind CSS 自定义。
- Ant Design 作为复杂基础组件工具箱，不作为整站视觉模板。
- 不直接使用 Ant Design 默认主题完成整站页面。
- 使用 Ant Design 时必须覆盖为 pxczxn 主题变量。
- Ant Design 适合：
  - Modal
  - Drawer
  - Dropdown
  - Select
  - DatePicker
  - Upload
  - Tooltip
  - Popconfirm
  - Pagination
  - Form
  - Table（仅工作台类页面）
- 文章编辑器使用 Tiptap / ProseMirror。
- Markdown 编辑器使用 CodeMirror 6。
- 文章渲染不依赖 Ant Design Typography 作为唯一排版方案。

最终关系：

```text
Tailwind CSS
= 页面与品牌视觉主体

Ant Design
= 按需使用的复杂交互组件
```

---

## 2.2 管理端 `pxczxn-admin`

技术栈：

```text
Vue 3
TypeScript
Vite
Naive UI
Pinia
Vue Router
```

使用原则：

- 管理端继续使用 Naive UI。
- 不引入 Ant Design Vue 与 Naive UI 混用。
- 不使用 React 重写现有管理后台。
- 后台页面优先使用 Naive UI 标准组件。
- 通过主题覆盖统一品牌色、状态色和圆角。
- 管理端强调信息密度、效率和稳定性，不追求博客端的视觉表现。

最终关系：

```text
pxczxn-web
= Tailwind CSS + Ant Design React（按需）

pxczxn-admin
= Naive UI
```

# 3. 三套主题

项目提供：

```ts
export type ThemeMode = 'light' | 'dark' | 'starry';
```

## 3.1 浅色主题

定位：

- 明亮
- 干净
- 清晰
- 适合日间阅读
- 默认主题

核心特征：

- 大面积低饱和浅灰背景
- 白色内容卡片
- 蓝色主色
- 轻边框和轻阴影

---

## 3.2 深色主题

定位：

- 克制
- 低干扰
- 夜间阅读
- 长时间沉浸

核心特征：

- 黑灰色背景
- 低亮度蓝色主色
- 卡片层级清晰
- 避免纯黑与纯白强烈对比

---

## 3.3 星空主题

定位：

- 独立品牌主题
- 深色基底
- 蓝紫星空氛围
- 强化平台识别度

核心特征：

- 深蓝黑背景
- 蓝紫主色
- 少量青色辅助
- 弱光晕
- 局部星点和星云渐变

规则：

- 星空主题是独立主题，不是深色主题的变体按钮。
- 星空元素仅用于页面背景、Hero、登录页、空状态和主题预览。
- 文章正文卡片、表格和编辑器不使用明显星点纹理。
- 跟随系统模式只在浅色和深色之间切换，不自动进入星空主题。

# 5. 字体规范

## 5.1 字体栈

中文正文推荐：

```css
font-family:
  Inter,
  "PingFang SC",
  "Microsoft YaHei",
  "Noto Sans SC",
  system-ui,
  sans-serif;
```

代码字体：

```css
font-family:
  "JetBrains Mono",
  "SFMono-Regular",
  Consolas,
  "Liberation Mono",
  monospace;
```

原则：

- 不强制用户下载自定义中文字体。
- 优先使用系统字体，保证加载速度和中文显示。
- Logo 和品牌字可以后续单独设计，不影响正文系统。

---

| Token | 桌面字号 | 移动端字号 | 行高 | 用途 |

| `display-md` | 40px | 32px | 1.2 | 大型页面标题 |
| `heading-1` | 32px | 28px | 1.25 | 文章标题、主页标题 |

| `heading-3` | 20px | 18px | 1.4 | 卡片标题 |
| `body-lg` | 18px | 17px | 1.8 | 文章正文 |
| `body-md` | 16px | 16px | 1.65 | 普通正文 |
| `body-sm` | 14px | 14px | 1.55 | 辅助文字 |
| `caption` | 12px | 12px | 1.5 | 时间、统计、标签 |

文章正文默认：

```text
桌面：18px / 1.8
移动端：17px / 1.8
```

管理端表格和表单正文默认：

```text
14px
```

---

## 5.3 字重

```text

500 Medium
600 Semibold
700 Bold
```

使用规则：

- 普通正文：400
- 按钮、Tab、导航：500
- 卡片标题：600
- 页面大标题：600 或 700
- 不使用 800、900 作为常规字重

# 6. 间距系统

采用 4px 基础网格。

```text
0  = 0px
1  = 4px
2  = 8px
3  = 12px
4  = 16px
5  = 20px
6  = 24px
8  = 32px
10 = 40px
12 = 48px
16 = 64px
20 = 80px
24 = 96px
```

常用规则：

| 场景 | 推荐间距 |
|---|---:|
| 图标与文字 | 8px |
| 表单标签与输入框 | 8px |
| 同组表单项 | 16px |
| 卡片内部 | 20px / 24px |
| 卡片之间 | 16px / 24px |
| 页面区块之间 | 32px / 48px |
| 页面左右边距 | 24px / 32px |
| 移动端左右边距 | 16px |

禁止使用大量无法归类的数值：

```text
13px
17px
19px
27px
```

特殊视觉对齐除外。

# 7. 圆角系统

| Token | 数值 | 用途 |
|---|---:|---|
| `radius-sm` | 6px | 标签、小按钮、Tooltip |
| `radius-md` | 8px | 输入框、普通按钮 |
| `radius-lg` | 12px | 卡片、Dropdown |
| `radius-xl` | 16px | 大卡片、Modal |
| `radius-2xl` | 24px | Hero、主题预览 |
| `radius-full` | 9999px | 头像、胶囊标签 |

默认规则：

- 普通按钮：8px
- 输入框：8px
- 内容卡片：12px
- 大型展示卡片：16px
- 弹窗：16px
- 头像：圆形

不要所有组件都使用超大圆角。


- 管理端减少阴影，优先使用边框和层级背景。

# 10. 响应式断点

推荐断点：

```text
sm  = 640px
md  = 768px
lg  = 1024px
xl  = 1280px
2xl = 1536px
```

规则：

- `< 768px`：移动端布局
- `768px ～ 1023px`：平板布局
- `>= 1024px`：桌面布局
- `>= 1280px`：完整三栏布局

不要只通过缩小字体适配移动端。

# 12. 图标规范

推荐图标库：

```text
Lucide React
Lucide Vue Next
```

用户端和管理端尽量使用同一图标语义。

规则：

- 常规图标：20px
- 辅助图标：16px
- 导航图标：20px
- 空状态图标：48px ～ 64px
- 线宽保持一致
- 不使用 Emoji 作为正式功能图标
- Emoji 仅允许出现在用户内容和轻量提示文案中

禁止：

- 同一页面混用多种图标风格
- 使用彩色图标代替状态体系
- 图标没有文字或 Tooltip，导致语义不清

# 13. 图片与媒体比例

| 场景 | 比例 |
|---|---|
| 文章封面 | 16:9 |
| 分享卡片 | 1.91:1 |
| 系列封面 | 16:9 |
| 收藏夹封面 | 4:3 |
| 博客主页背景 | 3:1 |
| 头像 / Logo | 1:1 |
| 动态图片 | 自适应，限制最大高度 |

规则：

- 图片使用 `object-fit: cover`
- 正文图片保持原比例
- 卡片图片需要固定比例防止布局跳动
- 图片加载前使用骨架或占位背景
- 必须支持 Alt 文本

# 15. 卡片规范

文章卡片必须包含：

- 封面，可选
- 标题
- 摘要
- 作者或博客
- 标签
- 发布时间或阅读时间
- 点赞、收藏、评论等数据

卡片规则：

- 标题最多两行
- 摘要最多三行
- 元信息使用 `text-tertiary`
- 卡片整体可点击
- 内部按钮必须阻止冒泡
- Hover 仅轻微上浮或边框变化
- 不做夸张缩放

---

# 16. 表单规范

- 标签位于输入框上方。
- 必填项使用清晰标识。
- 错误提示紧邻字段。
- 提交失败后保留用户输入。
- 密码框提供显示/隐藏按钮。
- 长表单分组展示。
- 危险操作单独区域展示。
- 保存按钮位置保持一致。
- 不使用仅靠 Placeholder 充当字段名称。

---

# 17. 编辑器规范

## 17.1 编辑器模式

```text

Markdown
```

默认：


切换规则：

- 切换前提示格式转换风险

- 不承诺无损往返转换
- 当前模式显示明确

## 17.2 编辑器布局

桌面：

```text
顶部操作栏
左侧正文编辑区
右侧发布设置栏
```

操作按钮：

```text
保存草稿
预览

```

规则：

- 保存草稿为次级按钮
- 提交审核或发布为主按钮
- 发布设置栏可折叠
- 自动保存状态必须显示
- 离开页面时检测未保存内容
- 工具栏吸顶但不遮挡正文

# 19. 表格规范

博客端表格：

- 主要用于团队工作台、投稿管理等功能页。
- 公开内容页尽量使用卡片或列表。
- 移动端优先改为卡片，不强制横向压缩表格。

管理端表格：

- 使用 Naive UI DataTable。
- 行高建议 44px ～ 48px。
- 操作列固定在右侧。
- 高频筛选放在表格上方。
- 批量操作必须二次确认。
- 状态使用统一 Badge。

# 20. 弹窗、抽屉和提示

## 20.1 Modal

适合：

- 确认操作
- 简短表单
- 权限设置
- 邀请成员

不适合：

- 长篇文章编辑
- 大量配置项
- 复杂多步骤流程

宽度：

```text
Small：420px
Medium：560px
Large：720px
```

---

## 20.2 Drawer

适合：

- 移动端目录
- 筛选面板
- 发布设置
- 通知详情
- 辅助信息

---

## 20.3 Toast

- 成功信息：3 秒
- 普通信息：4 秒
- 错误信息：不低于 5 秒
- 关键错误应同时显示页面内错误提示
- 不允许连续弹出大量重复 Toast

---

# 21. Loading、空状态与错误状态

每个页面必须考虑：

```text
Loading
Empty
Error
No Permission
Not Found
Offline
```

规则：

- 页面首次加载使用骨架屏。
- 按钮提交使用局部 Loading。
- 空状态需要说明原因和下一步操作。
- 403、404、内容下架和内容私密必须区分。
- 不使用统一“请求失败”覆盖所有错误。

---

# 22. 动画规范

动画时长：

```text
快速反馈：120ms
普通过渡：180ms
Modal / Drawer：240ms
复杂页面切换：300ms
```

缓动：

```css
cubic-bezier(0.2, 0, 0, 1)
```

允许：

- 按钮 Hover
- 卡片轻微上浮
- Modal / Drawer 进入
- Tab 指示器移动
- 点赞收藏反馈
- 星空背景轻微变化

禁止：

- 大面积持续漂浮
- 文章正文持续发光
- 页面进入时所有元素逐个飞入
- 动画阻塞用户操作
- 频繁缩放导致布局抖动

应支持：

```css
@media (prefers-reduced-motion: reduce)
```

```text

遮罩层：800
Drawer：900
Modal：1000
Toast：1200
Tooltip：1300
```

禁止组件自行随意使用：

```text
z-index: 99999
```

# 24. 无障碍规范

必须满足：

- 文字与背景达到合理对比度。
- 键盘可以访问主要功能。
- Focus 状态清晰可见。
- 按钮有明确文本或 `aria-label`。
- 表单错误可被辅助技术识别。
- 图片支持 Alt 文本。
- 不仅依赖颜色表达状态。
- Modal 打开后正确管理焦点。
- 关闭按钮点击区域足够大。
- 主题切换不能导致内容闪烁严重。

目标参考：

```text
WCAG 2.1 AA
```

# 25. 用户端与管理端差异

## 25.1 用户端

强调：

- 内容
- 品牌
- 阅读
- 创作
- 社区氛围

特点：

- 间距更宽松
- 卡片更轻
- 文章排版更精细
- 支持三套主题
- 星空主题拥有品牌表达

---

## 25.2 管理端

强调：

- 信息密度
- 操作效率
- 状态清晰
- 审计与权限

特点：

- 使用 Naive UI
- 表格和筛选器为主
- 间距更紧凑
- 减少大面积插画
- 不使用星空纹理干扰后台操作

管理端可以支持浅色和深色。

星空主题是否同步到管理端：

```text
V1 不强制
```

推荐星空主题主要用于用户端。

---

# 26. 禁止事项

禁止以下做法：

- 用户端完全套 Ant Design 默认视觉。
- 管理端混用 Ant Design Vue 和 Naive UI。
- 页面大量使用渐变按钮。
- 所有卡片都发光。
- 使用 Emoji 作为正式图标。
- 不同页面使用不同圆角系统。
- 直接硬编码大量颜色。
- 移动端只缩小桌面页面。
- 文章正文宽度超过 900px。
- 表单只有 Placeholder 没有标签。
- 状态只靠颜色表达。
- 星空主题影响正文可读性。
- 为了好看牺牲操作反馈和加载状态。

---

# 27. V1 UI 验收标准

- 用户端正确支持浅色、深色、星空三套主题。
- 所有核心组件使用语义色变量。
- 用户端页面视觉不呈现为传统后台模板。
- 管理端统一使用 Naive UI。
- 用户端 Ant Design 仅按需使用。
- 字体、间距、圆角、阴影符合统一规范。
- 核心页面具有桌面、平板、移动端布局。
- 表单具有完整错误和禁用状态。
- 页面具有 Loading、Empty、Error 状态。
- 键盘 Focus 清晰可见。
- 文章正文适合长时间阅读。
- 星空主题具有品牌识别，但不干扰正文。
- 核心流程可通过 Playwright 做视觉和交互验证。

# 28. 最终定稿

```text
pxczxn-web
```
