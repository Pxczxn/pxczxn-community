# M6-T002 原生手动发布交付说明

> 当前选择：不启用 GitHub 自动发布。发布由人工确认后执行原生脚本，不使用 Docker。

`Release Gates` 工作流仍保留在仓库中，供未来需要时启用持续集成；不配置 GitHub secrets 时不会连接生产主机。当前生产发布的必要步骤如下：

1. 在受控的 Linux 构建环境完成后端与两个前端的测试、构建，生成包含 Spring Boot JAR、React 运行时依赖、管理端静态文件和 `SHA256SUMS` 的发布包。
2. 执行 `native-backup.sh` 创建可恢复点。
3. 将发布包上传到主机临时目录，执行 `native-deploy-release.sh <提交版本> <发布包>`。
4. 脚本校验 SHA-256 清单，原子切换 systemd 后端和 React 服务以及 Nginx 管理端资源；健康检查失败会自动恢复原配置。
5. 若需要回退，执行 `native-rollback-release.sh <已存在的完整发布版本>`；它只回退应用代码，绝不改动数据库。

数据库迁移不由应用发布脚本自动执行。涉及迁移的版本必须先完成已评审的备份、迁移和 verify 流程，再允许发布应用；这样应用版本回退不会暗中回退或破坏数据库历史。
